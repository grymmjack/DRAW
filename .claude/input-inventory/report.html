Seams & gaps found

root cause
Cursor renders under the Preview window (and Color Mixer & Browser)
Cursor is baked into SCRN.CANVAS& (POINTER.BM:1577) before the upscale to screen 0 (SCREEN.BM:3595); the floating windows blit straight to screen 0 after (SCREEN.BM:3600-3602), covering it. No cursor equivalent of TOOLTIP_reblit_to_screen0. A code comment at POINTER.BM:1601 wrongly claims the cursor draws after preview. Fix: a cursor screen-0 reblit after the floating overlays in all 3 render paths.
systemic
THREE parallel sources of truth for pointer/z-order — the spaghetti
(1) Render order = a hardcoded draw sequence in SCREEN_render. (2) Region table z-order (REGION_hit_test%) — but all 14 panels share ZORDER_PANEL=100, so overlap winner is decided by region constant number, not stacking; 4 of 7 z-tiers are unused; and the whole mouse/wheel/hover layer is dispatched=FALSE (there's no wheel producer at all), so this table is dormant for pointer input. (3) Legacy geometry (*_is_over_area%, PREVIEW_hit_window%) in MOUSE.BM actually owns every click — a third map that can drift from the other two (e.g. REGION_PREVIEW vs PREVIEW_hit_window%, 1-frame skew). Fix: collapse to one declarative z-stack that drives render order AND hit-test order, with a real ZORDER_FLOATING tier.
kbd
Keyboard seams (13)
Ctrl+D double-mapped (307 vs 518); ./, grid keys advertised but unbound; F11/F12 use multiple physical keycodes; backtick quad-purposed; 5 declared context bits never set (modal blocking leans on legacy-runs-first); legacy-before-modern double-fire risk; chord-order sensitivity. All become tests.
