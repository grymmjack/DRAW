# Swatches panel (View > Swatches, actions 2600-2602)

A grid of color swatches from a swatch set, beside the palette strip (the strip
stays the document palette). Two layers:

| Layer | Files | Role |
|---|---|---|
| Data | `includes/QB64_GJ_LIB/SWATCH/SWATCH.BI/BM` (`SWS_`) | The set: load / save / edit. Pure data, no host globals, unit-tested headless by `SWATCH-TEST.BAS` (65 checks). Needs `QB64_GJ_LIB/COLOR/COLOR-SPACES` (sorting, Lab swatches). |
| Panel | `GUI/SWATCHES.BI/BM` (`SWP_`) | The window: layout, render, menus, input, sets list, import, QA dump. |

## The set (SWS_)

- `SWS(1 .. SWS_N)` of `SWATCH_ENTRY`: `c` (&HFFRRGGBB), `kind` (`SWS_KIND_COLOR` / `SPACE` = an empty cell / `BREAK` = next entry starts a row), `flags` (`SWS_FLAG_LOCK`, `SWS_FLAG_GROUP` + `grp` label), `sel`, `nm`.
- `SWS_COLS` = the columns the layout was made for (0 = unknown). `SWS_NAME`, `SWS_ERR` (why a load / save failed).
- Formats: `.aco` (v1 + v2 names; RGB / HSB / CMYK / Lab / gray), `.gpl` (`Columns:`; DRAW extras in `#SWS: SPACE | BREAK | LOCK | GROUP` comment lines other apps ignore), `.ase` (blocks C001 group start / C002 end / 0001 color; RGB / CMYK / LAB / Gray; a group starts a row - a BREAK, `SWS_FLAG_GROUP` + `grp` on its first color), `.act`, `.pal` (JASC + RIFF), `.hex`, `.txt` (Paint.NET), `.png` (`SWS_load_png%`: distinct opaque colors in reading order via a 4096-bucket hash, > 1024 refused, `SWS_COLS` = distinct colors on the first opaque row). `SWS_load%` dispatches on the extension, `SWS_can_load%` checks it. Saves: `SWS_save%(path)` dispatches - `.gpl`, `.aco`, `.ase` (RGB only; GROUP flag opens a group), `.act` (768 + count + FFFF), `.pal` (JASC, CRLF), `.hex`, `.txt`, `.png` (`SWS_save_png%(path, cols, cell, gap)`; breaks = new row, spaces transparent). **QB64:** `&HC001` is a negative INTEGER - write `&HC001&`; and `SWS_f32be!` / `SWS_f32be$` can't coexist (one name, two suffixes), hence `SWS_cvf32be!` / `SWS_mkf32be$`.
- Photoshop's auto names ("Swatch 12") are dropped on load (`SWS_auto_name%`).
- **Order for an .aco:** `SWS_COLS = SWS_guess_cols%` **before** `SWS_black_to_spaces TRUE`. The guess reads the black padding that lines the ramps up; after the conversion it is gone. Both `SWP_load_set` and `SWATCH-TEST --convert` follow this order.
- Edits (phase 2 will wire them to the panel): delete / move / copy / sort (`SWS_SORT_HUE / LIGHT / SAT / LUMA`, 0 = reverse) the selection with **locked entries staying exactly where they are**, remove duplicates, `SWS_snapshot$` / `SWS_restore` for undo.

## The panel (SWP_)

- FPANEL family member (title bar, drag, close, dock, per-panel scale, auto-hide while drawing over it, F11). Native image `SWP.panelImg`, `renderScale = FPANEL_scale% / displayScale`.
- **Floating** it has its own size: `CFG.SWATCHES_W / _H` (native px, 0 = default width `FPANEL_panel_w%` x 150), corner grip `SWP_GRIP`. **Docked** it is `DP_H_FLEX` like the Preview: `DOCK_apply_rect` -> `FPANEL_fit` -> `SWP_fit nw, nh` (0, 0 = floating) and the grid scrolls.
- IDs: `DP_SWATCH` = 15, `REGION_SWATCHES` = 33, `WZ_` slot in `GUI/WINZ`, `FPANEL_FLOAT_COUNT` slot 9, `WS_EL_SWATCHES` = 18 (workspaces), Settings → Panels → Panel Scale row.
- Layout (`SWP_layout`, two passes: the second when a scroll bar is needed): `SWATCHES_COLS` 0 = the set's own, -1 = fit, N; `CELL`, `GAP`, `STRETCH` (grow or shrink to the width), `SQUARE`, `BORDER`. `SWP_reflow` places entries (a BREAK ends the row) into `SWP_ER` / `SWP_EC`.
- Pick: `SWP_pick i, toBG` sets the same fields a palette-strip click sets (`PAINT_COLOR`, `DRAW_COLOR`, `PAL_FG_IDX` by find_index / closest, `POINTER.C`; the BG equivalents). Left = FG, right = BG.
- Menus are their own native image drawn after the panel (`SWP_render_menu`), not a POPUP: `POPUP_note_rect` would reblit canvas pixels over it. `SWP_MENU_SETS` (the set list) and `SWP_MENU_GEAR` (layout chips + checks, Load Swatches…, Open My Swatches Folder). Chips and checks keep the menu open; items close it. An open menu captures every click (the MOUSE gate lets it through even where `WZ_blocked` would stop it). `Esc` closes it (`INPUT/KEYBOARD.BM`, next to the dock-handle menu).
- Sets list (`SWP_scan_sets`): 0 = Document Palette (16 to a row, refreshed when `SWP_pal_sig$` changes), then My Swatches (`PATHS_data$("SWATCHES/")`), `ASSETS/SWATCHES/`, `ASSETS/PALETTES/`, My Palettes (+ `CREATED/`).
- **Listing never writes.** Only `SWP_import` and action 2602 create the My Swatches folder: a normal QA run does not isolate `XDG_DATA_HOME` (only `QA_USER_PROFILE=1` does), so a scan that created it would write into the real `~/.local/share/DRAW`.
- Import (`SWP_import`, action 2601): load any format -> guess columns -> (aco) black -> spaces -> save a `.gpl` copy in My Swatches with a unique name -> load that. The original is never written.

## Config (DRAW.cfg)

`SWATCHES_VISIBLE / SCALE / X / Y / W / H`, `SWATCHES_SET` (path; empty = the document palette; relative paths resolve from the DRAW folder), `SWATCHES_COLS` (0 / -1 / N), `CELL` (10), `GAP` (1), `STRETCH` (FALSE), `SQUARE` (TRUE), `BORDER` (FALSE), `BLACK_SPACERS` (TRUE).

## Shipped sets

`ASSETS/SWATCHES/*.gpl` are generated copies of Rick's Photoshop swatch sets (his `.aco` originals are never edited): GJ - Pixel Swatches (14 columns), GJ - Pixel Swatches 2 (26), GJ - Pixel Swatches All (26), Grymmjacks Essential Swatches - CS (16). Regenerate with `SWATCH-TEST --convert IN.aco OUT.gpl` (absolute paths: a QB64 program changes to its own folder at start).

  - `SWAT entries colors cols cellW cellH gap rows scrollY maxScroll fgIdx bgIdx menu menuRows setKey`
  - `SWATG` grid rect, set-button rect, gear rect
  - `SWATS selected anchor i ...` (up to 64 selected entries)
  - `SWATC i x y w h kind hex` (first 48 entries, every entry showing in the grid (up to 400), the last)
  - `SWATM x y w h rowH top`, `SWATMI row kind id chk x y w h label`, `SWATMC id k x y w h label` (chip k of chips row `id`; COLUMNS = 10, CELL = 11, GAP = 12)

- Fixtures: `QA/fixtures/make-swatch-fixtures.py` -> `swatches-edit.gpl` (8 columns: row 0 = 1-8 reds, row 1 = 9-12 greens (12 LOCKED) + a BREAK (13), row 2 = 14-19 blues, 20 SPACE, 21 Gold; row 1 columns 4-7 empty), `swatches-ramps.gpl` (8 columns, 160 colors, a SPACE at 6, entry 3 "Named Teal") and `swatches-pad.aco` (6 wide, 4 ramps + 2 black per row: 22 entries, 5 empty, 17 colors after loading).
- Tests: `swatches-panel.sh` (layout, FG/BG pick, wheel, gear chips, set list, Esc, dock + float), `swatches-aco.sh` (aco guess + black filler), `dock-native-swatches.sh` (the dock-native family), `swatches-dock-resize.sh`, `swatches-select.sh` (click / Shift / Ctrl / box / Ctrl+box / Ctrl+A / Esc / right-click), `swatches-select-scroll.sh` (scrolled range, box autoscroll, set switch clears, docked). `swatches` is in `dock-lib.sh`'s `DK_NATIVE` list (its floating position is saved in its own CFG keys, not `DOCK_FLOAT_*`).

## Selection (phase 2)

`SWS(i).sel` is the selection (the library's ops act on it). `SWP_click_entry` (plain = alone + FG via `SWP_pick`, Shift = range from `SWP.anchor`, Ctrl = toggle), box drag from an empty place (`SWP.boxing`, content coords so it survives scrolling; autoscrolls past the grid; Ctrl / Shift adds on top of `SWP.selBase`), `SWP_select_all`. Keys only while the pointer is on the panel (`SWP_has_keys%`): `SWP_key_input%` in `KEYBOARD_input_handler` (Esc, Ins), the rest through `SWP_take_action%`. `SWP_load_set` clears the selection.

## Editing (phase 2)

Every edit: `SWP_edit_begin%` (copy to My Swatches via `SWP_make_own%` if `SWP_is_mine%(setKey)` is false - the source is never written; a new undo step = `SWS_snapshot$`; the set's redo chain dropped) -> change `SWS()` -> `SWP_edit_end` (relayout + `SWP_save_now`, `.gpl` with `#SWS:` extras). Undo list `SWP_UNDO_*` (200 steps, keyed by set path, kind 0 undo / 1 redo), `SWP_undo redo%`. Keys while the pointer is on the panel: Del / Edit > Clear (CMD 306/308, intercepted at the top of `CMD_execute_action`), Ctrl+Z / Ctrl+Y (CMD 301 / 302). Dump `SWATE undo redo saves mine`. Tests run on a scratch data dir: `sw_isolate` (see memory qa-data-dir-not-isolated). Tests: `swatches-undo.sh`, `swatches-copy-names.sh`.

The edit menu (`SWP_MENU_EDIT` = 3): the ☰ button (`SWP_menu_btn_xy`, gear x - 15; `SWP_bar_at%` = 3) or Shift+right-click in the grid (`SWP.menuAtMouse` places it at the pointer; an unselected swatch is selected alone first). `SWP_build_edit` items 201 Add FG, 202 Delete, 203 Lock / Unlock, 206 Duplicate, 204 Insert Empty Cell, 205 Insert Row Break, 207 Remove Duplicates, 208 / 209 Select All / None, 210 / 211 Undo / Redo; header "N SELECTED". Subs `SWP_add_fg`, `SWP_lock_toggle`, `SWP_insert_kind`, `SWP_duplicate`, `SWP_remove_dups` (0 removed -> `SWP_edit_cancel` drops the undo step), `SWP_scroll_to`. Ops with nothing selected flash "nothing selected" BEFORE `SWP_edit_begin%`, so they make no copy and no undo step. Keys over the panel: `SWP_take_action%` at the top of `CMD_execute_action` takes 306 / 308 Del, 105 L (lock - else the Line tool), 310 Ctrl+A, 307 Ctrl+D, 301 / 302 undo / redo; `SWP_key_input%` takes Ins (`_KEYDOWN(20992)`) and Esc. **Esc with a menu open is handled in `SWP_key_input%` too** - closing it elsewhere left the edge memory stale, so the still-held Esc cleared the selection a frame later. Dump: `SWATG` adds the ☰ rect, `SWATC` adds flags (row breaks have no cell, so their numbers are skipped). QA helpers: `sw_menu_edit`, `sw_menu_click ID`, `sw_hexes` ("-" empty, "|" break from the numbering gap), `sw_empty_xy`. Tests: `swatches-edit-menu.sh`, `swatches-edit-ops.sh` (every op, then undo all back to the file), `swatches-edit-edges.sh` (nothing selected, locked duplicate, restart round trip).

Drag to move / copy: a press on a selected swatch arms `SWP.dragArm` and holds its click back (`SWP.dragPend`, replayed on the release by `SWP_click_with` with the press's modifiers - a plain click still selects it alone); a press on an unselected one clicks as before and arms the drag if it is now selected. 4 native px of travel = `dragMoving`; `SWP_drop_at&` = the entry to insert before (left / right half of a cell, past a row's end = after its last cell; `dragRow` puts the marker on the pointer's row), 0 off the panel. Autoscroll above / below the grid. Release: `SWP_drop d, ctrl` tries `SWS_move_selected` / `SWS_copy_selected` on the snapshot first - no change = no edit (no undo step, no copy) - then does it inside `SWP_edit_begin%` / `SWP_edit_end`. Locked entries keep their index (the lib's split/join locks). `SWP_owns_mouse%` now includes `boxing` and `dragArm`, so a box or a drag that leaves the panel keeps the mouse. Dump `SWATD on drop row`; status "MOVE n" / "COPY n". QA: `sw_drag_hold`, `sw_drag_entry`, `sw_left_of` / `sw_right_of`, `sw_dragstate`. Tests `swatches-drag.sh` (deferred clicks, in-place / off-panel no-ops, single, scattered + lock, locked in the selection, Ctrl copy), `swatches-drag-scroll.sh` (autoscroll to a hidden cell, docked).

Formats (F1): ☰ items 214 Load… (= action 2601) and 215 Save As… (action 2603, `SWP_save_as`: `DRAW_save_file$` in My Swatches, pre-filled with the set's name, no extension = `.gpl`, png uses the panel's columns / cell / gap; the panel keeps its set). Fixture `swatches-groups.ase` is written by the Python fixture script (an independent writer): Ink | Skin: Skin1-3 | Sky: Cyan (CMYK 1,0,0,0) Gray (0.5). Tests `swatches-ase.sh` (groups -> rows, names, CMYK / gray), `swatches-save-as.sh` (every format saved, headers, no extension, Load of ase / png / act / pal / txt / hex back to the same colors; the save dialog pre-fills the name, so the test BackSpaces it first).

Bridges (F2): `SWP_to_strip mode, atPos` (0 = replace, 1 = insert before strip index atPos, -1 = end; the selection, else every color; the strip never gets a color twice and holds 256; one `HISTORY_record_palette` step + `PALETTE_OPS_mark_document_palette`; FG / BG keep their colors, indices re-found with `PALETTE_STRIP_chip_for_color%`; `PCYC_validate` / `PCYC_on_insert` keep cycle ranges sane). `SWP_from_strip` (load the doc palette, `SWP_save_new_set%`), `SWP_from_image` (`LAYERS_flatten&` - apron / group safe; marquee box or wand mask via `_MEMIMAGE`; distinct opaque colors in reading order, 4096-bucket hash, > 1024 refused), `SWP_lospec` (lists `PATHS_data$("PALETTES/")` before `LOSPEC_show_dialog`, imports every new file after). `SWP_save_new_set%(name)` is the one "save SWS() as a unique .gpl in My Swatches and show it" (SWP_import uses it too). Drag: off the panel, `SWP_strip_drop_at%(rawX, rawY)` (`PALETTE_STRIP_in_bounds%` + `PALETTE_OPS_calc_strip_index%` + 1; no chip = the end) -> `SWP.dragStrip`; the release calls `SWP_to_strip 1, dragStrip`. Edit menu ids 216 / 217 to strip, 218 from strip, 219 from image (label "FROM SELECTION" with one), 223 Lospec; actions 2604-2608. Menus show the rows that fit below them (`SWP.menuVis`, set in `SWP_menu_open`, at most `SWP_MENU_VIS` = 40; fewer than 6 fit = it moves up) - a list taller than the room below used to move up over its own button. Dump: `SWATD ... dragStrip`, `SWATP n fgIdx hex...` (the strip), `SWATPG startX y chipW rowH perRow rows scroll visible`. QA: `sw_strip`, `sw_strip_xy K|end`, `sw_menu_find ID` (scrolls the menu to it; `sw_menu_click` uses it and sets `SM_LABEL`). Tests `swatches-strip.sh` (add / skip / undo, replace all / undo, drag after a chip and past the end, grid drop still moves, new set from strip), `swatches-from-image.sh` (empty canvas, two dots in reading order, marquee = selection set, Lospec with a faked download / nothing new).

List view, recent colors, Find FG (F3): `CFG.SWATCHES_VIEW` (gear chips row 32 GRID / LIST) - a list is the grid with one column: `SWP_size_cells` makes cells full width and `_MAX(cell, fontH + 2)` tall, `SWP_reflow` gives a row break its own divider row, `SWP_render_list_row` draws swatch + "#hex name" (selected = row fill; the inner selection frames are skipped; text only on whole rows), `SWP_drop_at&` uses the top / bottom half and `SWP_drop_xy%` a horizontal bar. Recent row (`CFG.SWATCHES_RECENT`, gear check 18, default off): `SWP_REC()` newest first, 32 max, `SWP_rec_push` (once each) from `SWP_tick` when the FG changes with the buttons up (a slider drag = one color; the starting FG is not pushed - `recLast`), kept in `CFG.SWATCHES_RECENT_COLORS` and saved 1.5 s after the last change while the row is on (the QA quit kills DRAW after 0.5 s, so the exit save is not enough); layout `recY` / `recH` (= the cell size, 6-14) / `recShown` above the grid; `SWP_rec_at%`, click = FG, right-click = BG via `SWP_pick_color`. Find FG (`SWP_find_fg`, edit menu 224, F = action 103 over the panel): exact match, else nearest OKLab (`CLR_rgb32_to_oklab`); selects it alone + `SWP_scroll_to`; the FG is unchanged. Dump `SWATV view recShown recN`, `SWATR k x y w h hex|-`. Test `swatches-list-recent.sh`.

## Phases

1. Panel + loading (done).
2. Editing: select ranges, add FG, delete, lock, move, sort, ramps, undo via `SWS_snapshot$`, save back to the `.gpl`.
3. More formats + bridges: `.ase` groups, strip <-> swatches, swatches from an image.

Edit color / rename / live edit (S5): a press on the swatch pressed < 0.4 s before (`SWP.clickI` / `clickT`, no modifiers) = double-click -> `SWP_edit_color` (`DRAW_pick_color&`; cancel = same color returned, the contract every caller uses; FG follows). Edit menu 212 Edit Color…, 213 Rename… (`SWP_rename`, `DRAW_input_box_ex$`; empty = cancel). Live edit: `SWP_tick` (DRAW.BAS, after `PALETTE_OPS_tick`) follows the one selected swatch (`liveIdx`); an FG change while `SWP_color_panel_has_mouse%` (Color Mixer / Advanced Color Picker / 3D Color Space under the pointer) recolors it, one undo step per mouse-down (`liveOpen`, `SWP_edit_end` on the mouse-up); FG changes from anywhere else only resync `liveLast`. Option `SWATCHES_LIVE_EDIT` (default TRUE, gear id 17). Status `COLOR PANELS EDIT #hex`. Dump `SWATN <first selected> <liveOpen> <FG hex> <name>`. Test `swatches-color-edit.sh` (dialog OK / Cancel, rename, mixer live, X elsewhere, option off, undo all) - needs `COLOR_MIXER_VISIBLE=1`; don't put the option under test in QA-OPTIONS (`--option` values are never saved).

Ramps + sort (S6), edit menu: 220 `SWP_ramp` (color entries from the first to the last selected, `DRAWER_gradient_lerp_color~&` = the Gradient Blend space, locked kept, nothing to change = no edit), 221 / 222 `SWP_insert_ramp 1|2` (FG->BG lerp / `CLR_oklch_ramp` with the CFG.RAMP_* settings; `CFG.RAMP_STEPS%` swatches after the last selected, else at the end; they become the selection), chips row 30 STEPS (= `CFG.RAMP_STEPS%`, shared with Palette > Generate OKLCh Ramp), chips row 31 SORT (an action row: the chip closes the menu and calls `SWP_sort mode`, `SWS_SORT_*`, 0 = reverse; the lib sorts the selection if 2+ are selected, else the set; only unlocked colors move). Sort / ramp try the change on a snapshot first, so an order or ramp that is already right makes no undo step. QA: `sw_chip_click ROW LABEL`. Test `swatches-ramp-sort.sh`.
