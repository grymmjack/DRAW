# Toolbar editor: button lists + Customize Toolbars

Plan: `PLANS/_/TOOLBAR-EDITOR-PLAN.md`. Branch `toolbar-editor` (2026-10).

## One button model (`GUI/BUTTON-LIST.BI/BM`, prefix `BL_`)

Each panel is an ordered list of entries `BL(panel, i)` with `BL_N(panel)` entries:

| panel | const | live source |
| --- | --- | --- |
| toolbox | `BL_TOOLBOX` (1) | **`TOOLBAR_BUTTON_ORDER()`** — `BL(BL_TOOLBOX)` is only a working copy (the editor loads it with `TBED_tb_load` and writes it back with `TOOLBAR_layout_apply%`) |
| edit bar | `BL_EDITBAR` (2) | `BL(BL_EDITBAR)` itself — `BL_bar_draw%` / `BL_bar_hit%` / `BL_bar_click` |
| advanced bar | `BL_ADVBAR` (3) | `BL(BL_ADVBAR)` itself |

Entry kinds: `BL_TOOL` (id = `TB_*` toolbox button), `BL_CMD` (id = action id), `BL_DIV` (divider: ends the row), `BL_GAP` (empty cell).

- The bars' old fixed tables (`EDIT_BAR_ITEMS`, `ADV_BAR_ITEMS`) are now only the **default lists** (`BL_set_default`) and the **icon catalog** (`BL_cmd_icon&` looks an action's icon up there).
- A command without an icon draws a **text tile**: up to 3 letters of its name in Tiny5 in an outline (`BL_tile_text$`, `BL_cmd_tile&`, 18x16, cached per action; freed on theme reload by `BL_free_tiles`).
- A command's name: the command palette's (`CMD_LIST`), else its **menu label** (`BL_menu_item%`) — ~30 menu-only commands (Paste in Place, Flip, …) have no palette entry.
- **Theme art for commands** (`BL_cmd_file_icon&`): a command with no bar icon loads `ASSETS/THEMES/<theme>/IMAGES/COMMANDS/<slug>.png` (16x16; `BL_cmd_icon&` falls through to it) and, for toolbox cells, `COMMANDS/TOOLBOX/<slug>.png` (11x11, drawn at cell scale; `TOOLBAR_draw_cmd_cell` tries it first). `<slug>` = `BL_cmd_slug$` (name, lower case, `-` joined) or `cmd-<id>`; active theme then DEFAULT; misses cached; freed with the tiles on theme reload. The work list for artists is `PLANS/_/COMMAND-ICONS.csv`, generated by `DEV/tools/command-icons.py` (mirrors `BL_cmd_slug$` / `BL_tile_text$` — change both together).
- Tooltips are keyed by entry: a command on a bar → its bar tooltip if it has one, else name + hotkey (`BL_cmd_tooltip`); a tool on a bar → its toolbox tooltip.
- A tool on a bar draws its 11px toolbox button centred in a 16px cell with the active-tool mark (`BL_draw_tool_button`); a click is `TOOLBAR_activate_tool%` (the toolbox click body, extracted).

### Toolbox codes (`TOOLBAR_BUTTON_ORDER`)

`-1` gap, `TB_DIV_CODE` (-2) divider (ends a row), `TB_CMD_BASE + action` (1000+) a command cell (`TOOLBAR_draw_cmd_cell`), else a `TB_*` tool. `TB_MAX_SLOTS` = 96. Row/col of a slot: `TOOLBAR_slot_rc` (dividers end rows); rows: `TOOLBAR_rows_for%`. **`TB_SLOT_X/Y(i)` is recorded for every slot during render** (gaps too) and every hit loop uses it — never recompute row/col from `i \ cols`.

### Names in workspace files

Existing names stay (`move`, `undo`, `preview`, …); any other command is `cmd:<action id>` (a bare number also works); `|` divider; `-` gap. Bar names (`undo`, …) are valid in `[TOOLBOX] BUTTONS=` too (`BL_bar_cmd_by_name%`). `[EDIT_BAR]/[ADVANCED_BAR] ORDER=` is an ordered list; the legacy `BUTTONS=` is a visibility filter over the default order (`WS_apply_bar_list%`).

## Customize Toolbars (`GUI/TOOLBAR-EDITOR.BI/BM`, prefix `TBED_`)

Non-modal floating window, same frame model as the Pen Pressure panel but drawn at the **dialog scale** (`TBED_scale%` = `USCALE.dialog`, like Edit → Settings — not `USCALE.mixer`, which `SCALE_RATIO_MIXER=.5` halves), about Settings' size (`FPANEL_*` look, Tiny5, `REGION_TOOLBAR_EDITOR` = 31, 7th window in `FPANEL_float_region%`, F11 hide-all, auto-hide while drawing over it). Opened by action **2460** (View menu, command palette, `TBED_ACTION`) and the dock handle menu → **Customize Buttons…** (`DOCK_ACT_CUSTOMIZE`) on the toolbox / bars.

- **Available** list: the toolbox tools (`TOOLS`), then commands by `CMD_CAT_*`, then `MENU COMMANDS` (menu rows the palette lacks) — minus what the tab's panel shows; filtered by the search text. Tool-select commands that duplicate toolbox buttons are hidden (`TBED_TOOL_ACTS$`). Rebuilt when `TBED.avDirty` or the panel list's checksum (`TBED_list_sig&`) changes.
- **Every change** goes `TBED_begin` (snapshot all three panels) → change `BL()` → `TBED_commit_mask(mask)` (apply each panel, then `TBED_save%(mask)`). Ops: `TBED_op_add_to`, `TBED_op_remove_at`, `TBED_op_move(srcPanel, srcIdx, dstPanel, dstAt)` (same panel or across), `TBED_op_insert` (divider / gap), `TBED_op_reset`, `TBED_op_cols`.
- **Saving is always into a workspace** (`TBED_save%`): in a workspace → `WSC_load` + `TBED_store_keys` + `WSC_save%` (a built-in gets a user copy). In Default → a name prompt (`DRAW_input_box_ex$`); a new workspace based on Default (`WSC_capture_layout` + the panel keys), switched to with `WSC_save_and_use`. Cancel → every touched panel is put back from the snapshot.
- Keys: the search field takes typing (`TBED_keys%` from `KEYBOARD_input_handler`); `TBED_typing%` blocks the central dispatcher, the eraser-hold handler and Space-pan while typing, and the Delete binding while Delete removes an entry.

The workspace configurator's Toolbox and Bars tabs have a **Customize Toolbars…** row (`WSC_editor_button`): it saves pending edits, switches to the selected workspace and opens the editor after the modal loop (`WSC.openEditor`). The Bars tab's checkboxes edit `ORDER=` when the workspace has one (else `BUTTONS=`).

### Edit mode (while the window is shown)

`TBED_edit_mode%`. `MOUSE.BM` routes a left press on the toolbox / bars to `TBED_panel_press%` instead of running the button (right / middle clicks do nothing there). The press selects the entry in the editor (switching its tab) and starts a drag (`TBED.itemDrag = 2`, `itemFromPanel`); `TBED_item_drag` tracks the drop target each frame (the editor's lists, or a real panel via `TBED_panel_at%` + `TBED_panel_insert_at%`, which also sets the insertion line `TBED.markX1..Y2`). Release: moved onto a list / panel, removed when dropped on Available or off every panel. Dragging an Available row onto a panel adds it there. `TBED_draw_panel_marks` draws (on screen 0, after the window) the selected entry's outline on its panel, the insertion line, and the dragged entry under the pointer. `UI_CHROME_CLICKED` is held TRUE through the whole drag so no tool stroke starts.

## QA

- `--option WORKSPACES_DIR=<path>` (run-only, never saved; `WS_DIR_OVERRIDE`) moves the user workspaces folder so tests never write the user's own.
- The dock layout dump (`DOCK_DUMP=<path>`) also carries `BTN` (every panel entry + rect), `TBED` (state, current tool, workspace) and `TBC` (the window's controls) lines — `TBED_dump$`. Helpers: `QA/tbed-lib.sh`. Tests: `QA/tests/tbed-*.sh`.

## Gotchas

- `TBED_AV_HEADER` vs a function named `TBED_av_header$` → "Name already in use": QB64 names are case-insensitive across CONST / FUNCTION.
- The bar entry rects (`BL().x/y/w/h`) are set while drawing; 0 size = not drawn this frame (scrolled away, a divider).
- The toolbox must keep one button (`TBED_op_remove_at` refuses the last).
