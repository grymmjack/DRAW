Building a Krita-style **Advanced Color Selector** into DRAW (user request 2026-09-07). User pasted Krita screenshots showing the docker + its config tabs: Color Selector, Behavior, Shade Selector, Color History, Colors from Image.

**Architecture (user-directed):** a standalone library widget `QB64_GJ_ADV_COLOR_PICKER` in the `includes/QB64_GJ_LIB` submodule (sibling to the `COLOR_PICKER`/CP module), wrapped by a DRAW floating panel `GUI/ADV-COLOR-PICKER.BI/BM` — exactly how `COLOR-MIXER` wraps CP. Widget files: `ADV_COLOR_PICKER/ACP-TYPES.BI`, `ACP-CORE.BM`, leader `ADV-COLOR-PICKER.BI/BM`, plus `ACP-TEST.BAS` (interactive) and `ACP-PROBE.BAS` (headless logic checks). DRAW includes the sub-files directly (not the leaders), per the submodule convention.

**Naming:** menu + command labels are "ADVANCED COLOR PICKER" (user OK'd; distinct from "COLOR MIXER"). Action id **2023**. Region `REGION_ADV_COLOR_PICKER = 28` (20 collided with PIXEL_COACH — regions run past TOOLTIP=19 up to 27). Toggle entry points: View menu, **Ctrl+Shift+M** (INPUT.BM dispatched binding, keycode 109 + CTRL+SHIFT), and **middle-click the Color Mixer organizer button** (ORG_COLOR_MIXER in ORGANIZER_handle_middle_click%).

**Phases:** 1 = hue ring + SV triangle, HSV (DONE, merged). 2 = DRAW floating panel + entry points + FG/BG (DONE, merged: DRAW #115, submodule #25). 3 = Shade Selector, 3 rows value/sat/hue (DONE: submodule PR #26). 3b = shade config in Settings > PANELS > "Advanced Color Picker" (patches/row + value/sat/hue spread spinners; CFG.ADV_COLOR_PICKER_SHADE_* pushed to ACP_STATE.shade* each render — pure render params, no resize). 3c = **quantize-to-steps** (CFG.ADV_COLOR_PICKER_QUANTIZE, 0=off/2-32): snaps triangle S/V (`ACP_quantize_unit!`) AND hue ring (`ACP_quantize_hue!`) to N steps and renders them banded; `ACP_set_quantize` rebuilds the ring + re-snaps on change, wrapper calls it each frame (cheap no-op when unchanged). 3d = **preset shade line-sets** (DONE). Widget generalized to the Krita delta+shift model: shared arrays `ACP_shadeDH/DS/DV/SH/SS/SV(0..ACP_SHADE_MAX_LINES-1)` + `ACP_STATE.shadeLineCount%`; `ACP_shade_color` = base + c*delta + shift per HSV axis; `ACP_set_shade_line`, `ACP_shade_area_h%`, `ACP_apply_shade_layout` (reallocs imgHandle when line count changes — the widget's height is now runtime, NOT a CONST). DRAW: `CFG.ADV_COLOR_PICKER_SHADE_PRESET` (0 Basic/1 +Warm-Cool/2 Full, dropdown ddId 60 in Settings) + `..._WARMCOOL` (deg). Wrapper `ADVCP_apply_shade_config` builds the lines from preset+spreads each render and resizes the panel (panelImg + dispW/H) when line count changes. Warm/cool line = value spread (DV) + uniform ±hue shift (SH). Full adds rich-shadow (DS negative) + fine-hue. NOTE for future per-line editor: the widget model already supports it; only a UI is missing. 3e = **Color History** (DONE): widget owns a recent-colors strip below the shades (`ACP_history()` ring, `ACP_history_push` dedup-to-front, `ACP_render_history`, `ACP_history_hit%`; `ACP_STATE.historyShow%`/`historyCount%`; height via `ACP_history_area_h%`). Wrapper pushes `PAINT_COLOR` on stroke commit (`HISTORY_saved_this_frame%` edge), click routes FG/BG via editTarget. `CFG.ADV_COLOR_PICKER_HISTORY` toggle (Settings checkbox). **User said the ADV color picker is feature-complete for their needs — NO color models (HSV/HSL/HSI/HSY) and NO colors-from-image wanted.** Later: color models HSV/HSL/HSI/HSY; Color History; Colors-from-Image; patch height / line height.

**Standing requirement:** ALL ACP configuration must live in DRAW's **Settings dialog** (mirroring Krita's config tabs), added incrementally as each phase introduces real options — NOT a separate config panel. See [[settings-three-doc-paths]] and gotcha #15 style discipline for any new state.

**Architecture rule (user-enforced):** ALL picker functionality — wheel, triangle, shade selector, and future chips — lives in the LIBRARY widget (`ACP`, submodule), NOT the DRAW wrapper. The wrapper (`ADVCP`) only frames it (title bar, drag, screen-0 blit), sizes the panel from `ACP_STATE.w`/`.h` (the widget owns its height, incl. the shade area = `ACP_SHADE_AREA_H` below the wheel), and maps the widget's single "current color changed" event to FG or BG via `ADVCP.editTarget`. Shade selector = 3 rows (value/sat/hue) under the wheel in `ACP_render_shades`/`ACP_shade_hit%`/`ACP_shade_color~&`; a shade click calls `ACP_set_rgb` so the wheel + rows recompute around it.

**UPDATE (user, 2026-09-07): dropped right-click=BG entirely.** Now LEFT-click everywhere in the picker = set FG; FG/BG swap is the X key's job (cleaner). RIGHT-click is repurposed for context menus. 3f = **history context menu** (DONE): right-click the history strip → a small 2-item menu (drawn to a native `ADVCP.cmImg` buffer, upscaled to screen 0 like the panel; state `ADVCP.cmOpen/cmX/cmY/cmW/cmHover`; MOUSE.BM dispatch calls ADVCP_mouse_input when `cmOpen`): **"Create Palette"** → `ADVCP_history_to_palette` writes the history colors to `PATHS_data$("PALETTES/CREATED/")*.gpl`, rescans + `PALETTE_LOADER_load_by_index%` (loads into the palette bar, switches to it — mirrors `PALETTE_LOADER_create_from_image`), and **"Clear History"** → `ACP_history_clear`. Plus a **"COLOR HISTORY"** label in **Tiny5** (`./ASSETS/FONTS/Tiny5-Regular.ttf`, loaded into `ADVCP.labelFont`) drawn above the strip; widget reserves `ACP_HISTORY_LABEL_H` for it via `ACP_history_top%`/`ACP_over_history%`.

3g = per-row **labels** (Tiny5, `ADVCP_lineName()`, `ACP_SHADE_ROW_LABEL_H`=15 reserves space above each row via `ACP_shade_row_pitch%`/`ACP_shade_row_label_y%`), **shade curve** Linear/Exponential (`ACP_STATE.shadeCurveExp`, exp does `c'=sign(c)|c|^2.5`), title = "ADVANCED COLOR PICKER". Rows now: VALUE, SATURATION, HUE, **HUE NEIGHBORS**, WARM, COOL, RICH SHADOW, FINE HUE (line indices fixed so names map). HUE NEIGHBORS range is **draggable on the ring**: big marker = current hue, two small markers at hue±`ACP_STATE.hueNeighborRange` (drag either → `ACP_pick_neighbor` sets range symmetrically; `ACP_DRAG_NEIGHBOR`, `ACP_near_neighbor_marker%`, `ACP_neighbor_marker_pos`). Persisted via `CFG.ADV_COLOR_PICKER_HUE_NEIGHBORS` (wrapper writes it each frame from ACP_STATE, reads on init — so Settings RESET won't reset this one field until re-init; acceptable). CFG toggles: SHADE_LABELS, SHADE_CURVE (dropdown ddId 61).

**OBSOLETE FG/BG convention (superseded above):** was LEFT=foreground, RIGHT=background. On the wheel: right-drag the ring = BG hue in place, right-click the triangle = BG saturation/value. Implemented in the wrapper via `ADVCP.editTarget%` (0=FG,1=BG): a right-press loads the current BG into the widget so the ring/triangle edit BG; on right-release the wheel reverts to showing FG. `ADVCP_sync_from_paint` skips while editTarget=1. The widget (ACP) stays color-agnostic — only the DRAW wrapper knows FG vs BG. Apply the same left=FG/right=BG rule to shade-selector patches, history chips, colors-from-image, etc.

**Makefile:** already depends on every .BI/.BM via a `find` (Makefile lines ~87-103), so include-only edits DO trigger rebuilds. A stale "Nothing to be done" only happens if you edit a source WHILE a build is mid-flight (output ends up newer than the edit). No Makefile change needed.
