How to read this. A routine is listed when its name is referenced 0 times outside its own body (ext 0) anywhere in the tree — defined but never called by name. Verify before deleting: a routine reached only through action-ID dispatch (CMD_execute_action CASE <id>), an event table, or a name built in a string can appear here as a false positive. refs counts every occurrence including self-assignment of a FUNCTION's return value, so a high refs with ext 0 just means all uses are internal.
Dependency code, broken out — compiled files only. Only the dependency files actually reached via $INCLUDE from the build are counted here (a submodule often ships far more than a project uses). By project = how many times each routine's name is referenced from the host project's OWN files (0 = the project never calls it directly — used only inside the dependency, or dead weight). Ext = references outside the routine's own body.
C interop (DECLARE LIBRARY). Every external-C binding compiled into the build. Each static DECLARE LIBRARY makes QB64-PE emit a probe program and compile it first to resolve the C symbols & signatures — that is the extra transpile pass you see reach 100% before Compiling C++ code…. DYNAMIC LIBRARY is resolved at runtime and does not probe. Fewer distinct static libraries = a shorter pre-pass (the number of blocks per library doesn't add passes). C source is the header/source QB64 binds (resolved on this machine).
