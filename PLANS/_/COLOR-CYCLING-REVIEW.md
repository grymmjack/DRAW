## Try it in two minutes

```bash
git checkout palette-cycling && make
./DRAW.run "SAMPLES/COLOR CYCLING/waterfall.draw"     # then press Shift+Tab
```

1. **Shift+Tab** starts cycling. Hover the swatches to read the ranges in the status bar.
2. Turn on **Palette Ops** (Organizer button), then **Ctrl+drag** across a few swatches to make a range. **Ctrl+click** changes its direction, **Ctrl+right-click** pauses it, **Ctrl+wheel** changes its speed, and **Ctrl+middle-click** deletes it.
3. **File → Color Cycling** has the five exports and *Open DeluxePaint / GrafX2 File…*.
4. `qb64pe -x "SAMPLES/COLOR CYCLING/fire.bas" && "SAMPLES/COLOR CYCLING/fire"` runs the generated program.
5. Open `SAMPLES/COLOR CYCLING/*.gif` or `*.lbm` in GrafX2 to check the ranges cycle there too.

## Choices I made that you may want to change

1. **Ping-pong goes 0, 1, … n-1, … 1** (period `2(n-1)`), so the end colors aren't repeated. The plan's formula repeated them.
2. **The strip swatches cycle too** while cycling runs, as in DeluxePaint. If clicking a moving swatch feels confusing, a setting could keep the strip still.
3. **A menu command targets** the hovered swatch's range, then the selected swatch's, then the FG color's.
4. **A new range replaces any range it overlaps**, rather than being refused.
5. **The default speed is 10 steps/s.** The Ctrl+Wheel table runs 0.5, 1, 1.5, 2, 3, 4, 5, 6, 8, 10, 12, 15, 20, 30, 40, 60.
6. **Imports**: inactive or rate-0 CRNG ranges come in *paused* at the default speed, so the artist's ranges aren't lost (DeluxePaint files often store several inactive ranges). Duplicate palette colors that matter, meaning used by pixels or inside a range, are moved to the nearest free RGB (a level or two), because in DRAW the first swatch with a color owns its pixels.
7. **Ping-pong and paused state** survive GIF and LBM round trips through private `DRAWCYCL` / `DRCY` blocks. CRNG alone can only say forward / reverse / active.
8. **Batch PBM**: `--export x.bbm` or `x.pbm.lbm`, because `.pbm` belongs to netpbm. The menu has separate ILBM and PBM items.
9. **Behavior change outside cycling, in `DRW_open_dialog`**: opening any file other than `.draw`/`.png` no longer makes it the Ctrl+S target. Before this, *Open → some.gif → Ctrl+S* overwrote the GIF (or BMP, or LBM) with project data under the old name. It now writes `some.draw` next to it, the same as the Open Image path and ASE/PSD already did.
10. **Messages say "Palette Ops"** to match the UI and manual. Code comments still say "Color Ops".

## Known limits

- A pixel cycles **only when its RGB exactly matches a swatch inside a range**. Opacity below 100% and non-Normal blend modes produce in-between colors that don't cycle (the manual says so). Duplicates get a red checker band, and *Check Duplicate Colors* lists them.
- **macOS / Windows are untested.** On *GLUT* builds, macOS turns **Ctrl+click into a right click** (`INSTALL/MAC-USERS-README.md`), which would break the Ctrl gestures on the strip. The current GLFW toolchain shouldn't remap clicks, but I couldn't check it on a Mac. The Palette → Color Cycling menu works regardless.
- **The animated GIF** loops exactly when the range periods fit within 60 s / 1000 frames (the samples loop every 2–4 s). Otherwise it's cut with a log warning. Times are rounded to 1/50 s.
- **Not supported:** HAM, 24-bit ILBM, ANIM, LBM pixel aspect (320×200 opens square), GIFs without ranges keeping their palette (they load as plain images, as before).
- **Third-party programs were checked at the file level only.** GrafX2-made `test.gif` round-trips its CRNG bytes exactly; ffmpeg and netpbm `ilbmtoppm` decode DRAW's GIF/ILBM/PBM pixel-exact; real PyDPainter files and Gold-Box-era DeluxePaint LBMs import correctly. I did **not** open DRAW's files in GrafX2's or DeluxePaint's own UI. That's the manual checklist's EXPORTS section.
- **Performance** was measured under Xvfb, where all GL is software. With 320×200 and 2 ranges, cycling costs the same CPU as any other active state, such as marching ants (~58% under Xvfb). With 1920×1080 and every pixel cycling at 30 steps/s, layer time is 4 ms/frame. It was 30 ms before the overlay and step-only work in `e073e1f7`. A real GPU should do much better.

## Worth a look outside this feature

- `SAFE_FREEIMAGE` (`CORE/HELPERS.BM`) **doesn't zero the handle**. Any `SAFE_FREEIMAGE h` followed by `IF h >= -1 THEN h = _NEWIMAGE(...)` keeps a freed handle. I zeroed my own uses; other call sites may have the same pattern.
- `PAL_find_closest%` (`GUI/PALETTE.BM`) only searches palette entries 0–15. The new indexer has its own nearest-color search, but older callers use this one.
