BUG-1 Paste leaves a stale magic-wand selection mask You reported Fixed
SymptomAfter copy/paste, the magic wand selects regions that don't match the visible content — "selects things that aren't there."
Root causeClipboard & wand share one buffer: MARQUEE.SELECTION_MASK. Paste calls TOOLS_reset_all FALSE which preserves the wand mask (as a clip), but overwrites MARQUEE.BOX — leaving the mask's WAND_MIN/MAX bounds stale. MOVE_apply_transform then drags that stale mask around.
FixClear the wand mask on paste — MAGIC_WAND_reset in CLIPBOARD_paste (TOOLS/SELECTION.BM), before the MOVE float is built. The paste rectangle is the real selection.
Verifyseam-copy-then-wand GREEN + manual confirm of ants geometry
BUG-2 Orphaned TRANSFORM overlay — content un-erasable until reload You reported Fixed
SymptomVisible pixels on the canvas the eraser can't remove; reloading the file clears them — "things on the doc I could not erase until I loaded the file again."
Root causeEdit→Transform sets TRANSFORM.ACTIVE. Switching tools ran TOOLS_reset_all, which never committed/cancelled the transform — so the overlay kept baking its warped preview onto the canvas every frame. Those pixels live on no layer, so the eraser can't touch them; mouse clicks were also hijacked by the transform handles.
FixCommit the transform on tool switch — TOOLS_reset_all (GUI/GUI.BM) now commits an active overlay first, preserving the destination tool.
Verifyseam-transform-then + seam-eraser-reaches-all GREEN — both were RED before the fix
BUG-3 MOVE float buffers leaked on every Open / New Fixed
Root causeAll three doc-creation paths call MOVE_init, which only zeroes SELECTION_IMAGE / PREVIEW_BUFFER (it assumes the caller already freed them). None freed first, so a live paste/move float leaked its buffers — including a canvas-sized PREVIEW_BUFFER — on every Open/New.
FixFree the float buffers before MOVE_init in DRW_load_binary / DRW_new_canvas / DRW_create_canvas_at_size (TOOLS/DRW.BM).
VerifyCompiles clean (a leak — not visually testable); reset paths audited & aligned.
BUG-7 Soft anti-aliased eraser shipped dormant (never wired) Fixed
Root causeThe 2.0.0 Phase-2c soft eraser (PAINT_erase_circle_aa) and its wrapper ERASER_draw_at had zero callers — the live stroke goes through PAINT_on, which hard-erases the full circle with AA on (works, but no feathered edge).
FixRoute transparent AA stamps to PAINT_erase_circle_aa in both stamp sites (TOOLS/BRUSH.BM). Entirely inside the IF CFG.ANTIALIAS% branch → AA-off is byte-identical.
VerifyCompiles clean; seam + regression suites GREEN. Eyeball recommended: enable AA, erase over a filled area.

Round 2 · deep hunt · fixed & verified
BUG-14 Paint tools wrote raw coords into a promoted apron buffer (systemic) Fixed
SymptomAfter a Move pushed content past the canvas edge (promoting the layer), every paint tool — brush, dot, line, rect, ellipse, spray, eraser, smart-shapes — landed strokes ~50% off, off the visible canvas.
Root causeA promoted layer's buffer is larger than the canvas; canvas (x,y) maps to buffer (x+apronW, y+apronH). The paint primitives wrote raw canvas coords (gotcha #14, live & systemic).
FixOne apron offset in the 3 low-level pixel writers (all stamps funnel through them) — clip/symmetry stay in canvas coords. Byte-identical for compact layers. Also fixes BUG-16 (smart eraser).
BUG-26 Text / AI layer data lost or misattributed on save (sparse-array class) Fixed
SymptomMake a text layer, delete a layer below it, save & reload → the editable text is gone (or attached to the wrong layer).
Root causeThe layer array is sparse after a delete; the text/AI save looped 1 TO LAYER_COUNT% and stored the raw slot as the key — dropping high-slot layers and mis-keying the rest. Same class hit Palette-Ops replace (BUG-25) and export naming.
FixLoop 1 TO MAX_LAYERS + store slotToSeq%() at every site (`DRW.BM`, `PALETTE-OPS.BM`, `HISTORY.BM`, `FILE-BAS.BM`).

BUG-44 Palette-strip page-scroll crashes on a 16-color palette Fixed · crash
SymptomShift/Ctrl + wheel-up over the palette strip with a 16-color palette (the pixel-art norm) → crash.
Root causeA one-shot `+/-` wrap left the scroll offset negative when page-size (32/64) > color count; render then read PAL(-15) — subscript out of range (QB64 MOD keeps the sign).
FixReal modulo normalization into [0, count-1].
